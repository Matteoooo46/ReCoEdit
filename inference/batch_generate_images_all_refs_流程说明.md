# 批量商品广告图像自动生成流程说明

本文档详细描述了 `batch_generate_images_all_refs.py` 脚本的端到端数据生成过程。该脚本的目标是：**给定一批商品 ID，自动为每个商品生成一套包含人物定妆照和六张分镜图的商业广告素材**。

---

## 一、整体概览

整个流程是一个全自动的端到端流水线，输入是一个 CSV 文件（包含 `item_id` 和 `first_industry_name` 两个字段），输出是每个商品一个独立的工作目录，其中包含商品参考图、人物定妆照、分镜剧本 JSON 和六张分镜图。

脚本使用了以下外部服务和模型：
- **快手商品信息中心客户端（KwaishopProductItemCenterClient）**：根据商品 ID 拉取商品的结构化信息（标题、卖点、行业分类、商品图片 URL 等）。
- **Qwen3-VL-30B 视觉语言模型**：用于从商品图片中智能筛选主图和副图。
- **Gemini 2.5 Pro 多模态模型**（通过内网 LLM Gateway 调用）：承担三项核心任务——设计人物角色、从零创作分镜剧本、以及（可选）基于参考视频进行分镜迁移。
- **Novita API（Gemini 2.5 Flash Image）**：实际执行图像生成的外部 API，支持文生图和垫图编辑两种模式。
- **DeepSeek R1 文本模型**（通过百度千帆调用）：脚本中已配置客户端但当前主流程未直接使用。

## 二、核心数据生成流程（按商品逐个处理）

脚本读取 CSV 文件，过滤掉空值行，将 `item_id` 转换为整数，然后遍历每个商品执行以下步骤。已经完成处理的商品（工作目录下存在 `final_storyboard_script.json` 和 `item_info.json`）会被自动跳过，实现断点续跑。

### 步骤 A：商品信息提取与图片下载

#### A1. 获取商品结构化信息

脚本使用 `KwaishopProductItemCenterClient` 客户端，通过商品 ID 向快手商品信息中心发送同步请求，获取商品的完整结构化信息。返回的数据是一个嵌套的 protobuf 字典，包含商品标题（`itemTitle`）、商品 ID（`itemId`）、行业分类（一级和二级行业名称）、商品卖点（`sellingPoint`）、以及商品的属性信息（`itemCategoryProp`，包括品牌、风格、适用场景、适用季节、服饰功能、流行元素等）。这些信息被保存为 `item_info.json` 文件。如果该文件已存在则直接读取，避免重复请求。

#### A2. 提取商品文案与卖点

从商品结构化信息中递归提取以下关键文本字段：
- **商品标题**（`itemTitle`）：作为商品的主要文字描述。
- **商品卖点**（`sellingPoint`）：商品自身的营销卖点文案。
- **行业分类**：从一级和二级行业名称拼装成一句描述（例如"first industry name is 美妆, second industry name is 面部护理"）。
- **扩展卖点**：从 `itemCategoryProp` 中提取品牌、风格、适用场景、适用季节、服饰功能、流行元素等属性值，去重后用逗号拼接。特别地，品牌信息会被格式化为"XX品牌"，功能信息保留原值。

最终的商品文案由商品标题、自身卖点和扩展卖点三部分组合而成。

#### A3. 下载商品图片

从商品结构化信息中递归提取所有图片 URL（匹配 `.jpg`、`.jpeg`、`.png` 等常见图片扩展名）。图片 URL 如果是相对路径，则拼接快手图片 CDN 前缀 `https://s1-11661.kwimgs.com` 构成完整 URL。然后将所有图片下载到工作目录下的 `images` 子目录中。如果该目录已存在且图片数量达到原始 URL 数量的 80% 以上，则跳过下载。

#### A4. 智能筛选参考图

这是整个流程中一个关键的视觉理解环节。脚本使用 Qwen3-VL-30B 视觉语言模型，分两轮从下载的商品图片中筛选出最适合作为广告参考的主图和副图。

**第一轮：分批粗选**

将所有商品图片按每批 6 张进行分组。每张图片先缩放到短边 512 像素，然后转为 Base64 编码发送给 Qwen VL 模型。模型根据以下标准从每批中选出两张图：
- **主图（商品整体图）**：优先选择无广告文字、有模特穿戴、商品正面展示的完整商品图。
- **副图（商品细节图）**：优先选择无文字的局部细节图，若无合适细节图可返回 -1。

每批图片附带商品标题作为上下文，帮助模型判断。如果某批图片不足 2 张，则全部保留。模型调用带有 3 次重试机制。

**第二轮：最终精选**

将第一轮从各批次中选出的所有候选图片再次汇总，调用 Qwen VL 模型进行最终筛选，同样选出一张主图和一张副图。最终结果（通常为 1 到 2 张图片）被复制到工作目录下的 `reference_imgs` 子目录中，作为后续步骤的商品参考图。

### 步骤 B：人物角色设计与定妆照生成

#### B1. 人物角色设计

将步骤 A 中选出的商品参考图和组合好的商品文案（标题 + 卖点）一起发送给 Gemini 2.5 Pro 模型。模型被提示为一个专业的人物设计师，需要根据商品信息和参考图，设计一位适合该商品广告的主角。输出为严格的 JSON 格式，包含：
- **name**：角色名称。
- **description**：角色的详细视觉描述（英文），包括年龄、服装、发型、气质等，要求适合 AI 图像生成。

生成的 JSON 被保存为 `character_gen_prompt.json`。

#### B2. 定妆照生成

从角色描述的 JSON 中提取 `description` 字段，在其末尾拼接画质魔法后缀（"Cinematic, Photorealistic, 4K Commercial, High Quality, bright and vibrant lighting, Portrait Mode (竖屏 9:16), Aspect Ratio: 9:16"），构成最终的图像生成 Prompt。

然后调用 Novita API 的文生图接口（`gemini-2.5-flash-image-text-to-image`），设定画面比例为 9:16、尺寸为 1K，生成一张人物的商业定妆照，保存为 `final_lifestyle_image.png`。

Novita API 的调用过程为：向 Novita 发送 POST 请求，携带 Prompt 和参数，API 返回一个包含图片 URL 的 JSON 响应，脚本再下载该 URL 的图片内容并保存到本地。每次调用无论成功与否都会自动记录到 API 用量账本中。

### 步骤 C：分镜剧本创作

定妆照生成成功后，脚本调用 Gemini 2.5 Pro 模型从零开始创作分镜剧本。这一步的输入包括三个部分：
1. **商品文案**（步骤 A 中提取的标题和卖点）。
2. **商品首张参考图**（步骤 A 中选出的第一张主图）。
3. **刚生成的模特图**（步骤 B 中的定妆照）。

模型根据详细的系统 Prompt（`System_Prompt_scene_plot_v2`）完成以下创作任务：

- **剧情大纲（outline）**：定义人物设定（包括 ID、性别、年龄、风格、体型）和场景设定（包括 ID 和详细的物理空间描述）。如果商品图中有具体商品需要在场景中陈设，必须在场景描述中指明是哪张图片以及空间位置关系。
- **人物造型设定（characters_dressing）**：为每个人物在不同分镜中定义具体着装，每个造型有唯一 ID，指明属于哪个角色，并描述具体穿搭。如果是商品图中的商品，需标注"参考输入图片[编号]"。
- **分镜剧本（script）**：包含 6 个分镜。每个分镜包含镜头序号（1 到 6）、角色造型 ID、场景 ID、商品图片编号数组（纯商品空镜时使用）和纯视觉画面描述。要求 6 个分镜形成连贯叙事，巧妙转化商品卖点，且画面描述中**严禁出现任何文字信息**，只描述视觉元素。

模型调用带有 3 次重试机制，并对 500/502/503/504 等服务端错误进行 5 秒等待后重试。生成的 JSON 剧本中每个分镜的 `description` 字段都会被自动追加画质魔法后缀，然后保存为 `final_storyboard_script.json`。

### 步骤 D：分镜图循环生成

这是整个流程的最后一步，也是规模最大的一步。脚本循环遍历分镜剧本中的 6 个镜头，逐一调用 Novita API 生成对应的分镜图。

#### 垫图策略

每个镜头在生成时都会无条件垫入以下参考图（使用 Novita 的 `gemini-2.5-flash-image-edit` 垫图编辑接口）：

1. **历史帧（滑动窗口）**：最近生成的前 2 张分镜图，用于保持画面连贯性。第一个镜头没有历史帧。
2. **人物定妆照**（`final_lifestyle_image.png`）：无条件强制垫入，确保人物外观在所有分镜中保持一致。
3. **商品首张参考图**：无条件强制垫入，确保商品外观、颜色、材质在所有分镜中准确呈现。

所有参考图以 Base64 编码格式放入 API 请求的 `image_base64s` 字段中，与 Prompt 一起发送给 Novita API。

#### 生成与保存

每个镜头生成时使用的 Prompt 来自剧本中该镜头的 `description` 字段（已在步骤 C 中追加了画质后缀），前面加上"画面描述: "前缀。生成的图片按 `scene_1.png` 到 `scene_6.png` 的命名规则保存在工作目录下的 `storyboard_images_all_refs` 子目录中。

每个镜头生成成功后，其图片路径被加入历史帧队列（队列容量为 2，超过 2 张时移除最早的帧），供后续镜头作为连贯性参考。

## 四、追加功能：基于参考视频的分镜迁移（可选）

脚本中还包含一个未在主循环中默认启用的功能——`generate_transfer_script_by_gemini` 函数。该功能可以将一个已有的参考视频的脚本章节结构（JSON 格式），结合新商品的信息和图片，迁移生成新的分镜剧本。输入包括：
- 参考视频的结构化数据（JSON）。
- 新商品的文案描述。
- 新商品图片和人物角色图。

这允许用户用已有的优质视频模板来"套拍"新商品的广告，实现风格和结构的 1:1 复刻。

## 五、输出文件结构

每个商品处理完成后，其工作目录（位于 `/data/phd/kousiqi/zhitao/batch_product_images_all_refs/` 下，目录名格式为 `item_{商品ID}_{随机8位UUID}`）包含以下文件：

| 文件/目录 | 说明 |
|---|---|
| `item_info.json` | 从快手商品信息中心拉取的原始商品结构化信息 |
| `extracted_item_info.json` | 提取后的精简商品信息（标题、ID、卖点、行业分类） |
| `images/` | 下载的商品原始图片 |
| `reference_imgs/` | 经 Qwen VL 模型智能筛选后的参考图（1-2 张） |
| `character_gen_prompt.json` | Gemini 生成的人物角色描述 JSON（含 name 和 description） |
| `final_lifestyle_image.png` | Novita 生成的人物商业定妆照 |
| `final_storyboard_script.json` | Gemini 生成的完整分镜剧本 JSON（含 outline、characters_dressing 和 6 个分镜） |
| `storyboard_images_all_refs/` | Novita 生成的 6 张分镜图（scene_1.png 至 scene_6.png） |
| `process.log` | 整个处理过程的日志文件 |

## 六、错误处理与健壮性设计

脚本在多个环节实现了容错机制：

- **断点续跑**：启动时扫描输出目录，已完成（存在最终剧本）的商品自动跳过。
- **商品信息缓存**：`item_info.json` 和 `extracted_item_info.json` 若已存在则直接读取，避免重复请求。
- **图片下载缓存**：若 `images/` 目录下图片数量达标则跳过下载。
- **参考图缓存**：若 `reference_imgs/` 目录非空则跳过重选。
- **Qwen VL 调用重试**：选图环节单次失败最多重试 3 次，每次间隔 5 秒。
- **Gemini 调用重试**：分镜剧本生成失败最多重试 3 次，HTTP 5xx 错误间隔 5 秒重试。
- **Novita API 用量记账**：无论调用成功或失败都会持久化记录到 JSON 账本文件中，支持按 Key 和日期统计用量。
- **代理管理**：脚本开始时设置代理，结束时取消代理，确保后续网络环境不受影响。
- **全局异常捕获**：单个商品处理失败不会导致整个任务中断，错误会被打印并继续处理下一个商品。
